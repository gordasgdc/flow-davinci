# Workspace header candidate

Every OpenGate floating host can receive one compact Panels accessory in its existing native title bar. It does not create another window, another traffic-light set, or a new vertical row. Native Edit UI's main window is excluded. Compact/hidden titlebar styles retain the existing top-menu recovery route rather than forcing a title bar back on.

Each header lists only its own panel doors. The primary Timeline group (or largest remaining visible surface) also exposes All Panels using the exact existing Show Panel actions, plus floating-window doors. Secondary groups remain independent magnetic surfaces. Whole-group hide is stored separately from member hidden states, and calling a member clears the group's hidden state before revealing/selecting that member. Group snapshots persist that separate window door.

The native Workspace Toolbar's scoped `labelTitle` under `centerFrame` is the project-name source. Its text is observed and reflected into existing host titles, with a short local group suffix for secondary windows. When the native source cannot be resolved, the existing group title remains; source resolution is logged rather than inventing a project name. No project API, selection or project state is mutated. Project open/rename/switch remains a live acceptance requirement.

When Workspace Toolbar is grouped, its redundant per-panel header is hidden; it retains its native controls and detach control. The surrounding window keeps its single native header and pin light.

Logs cover project-source resolution/title updates, header scope, panel-door requests and group-window visibility. The hidden header fixture passes project text changes, local versus global scope, shared action identity, unchanged host height, original traffic-light count and non-overlapping header accessory. Native group fixtures exercise preservation of member doors when the whole group closes/opens. Live behavior is pending installation.

Compact-header follow-up: standard native chrome no longer reserves a second Qt grip row; compact chrome keeps its existing 28-pixel title area and exposes the same native Panels accessory. Project title discovery reads btnProjectsMainBarProjectList under UiProjectsMainBarImp, including while hidden, rather than the unrelated viewer centerFrame/labelTitle. Live project text still requires verification. The Panels menu offers Workspace Toolbar Controls > Interface Size and Float Separately without a second panel header. A small CompactToolbar owner constrains only the disposable floating/group wrapper to the current native toolbar row hint; native docking constraints are not changed. Scaling and floating delegate to the retained session and existing group ownership. Existing arrangements and native shortcut presets are not rewritten.

The standalone Workspace Toolbar uses one full-size-content strip: native traffic lights/pin at left, live toolbar controls in the center, Panels at right. Only the host's margins reserve horizontal accessory space. The native toolbar's margins, layout and constraints remain intact when transferred back into a group/native slot. Grouped toolbars use their existing controls row with no extra leaf label row. Native toolbar door events observed in the first trial preserve existing Media Pool and Inspector placements; deliberate placement commands remain separate from show/hide.

Toolbar callers/label regression follow-up: each session now retains an immutable panel title for tabs, internal headers and drawer labels. Project-bearing window titles cannot enter those labels. The Workspace Toolbar arrow detaches an attached toolbar into a real floating host; from that host it attaches above the Timeline's existing magnetic group. Explicit native docking remains a separate command. A dedicated ToolbarDoors module adds Source Monitor, Program Monitor, Timeline and Page Navigation through the existing door functions, preserving leased placement. Float pin preference uses toolbar_float_pinned, defaults on, and is preserved independently of group pin state. Toolbar overflow reuses the reversible native-content scroll wrapper with horizontal scrolling and no vertical scrollbar; CompactToolbar reserves scroll height only when needed. Hidden tests exercise duplicate wiring, checked-state refresh and reaching the last overflowing control; displayed group tests verify project-bearing window titles do not change panel labels. Live Resolve behavior remains pending a new install.
